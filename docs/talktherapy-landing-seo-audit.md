# TalkTherapy landing page SEO audit

**Scope:** The public homepage route (`/`) as it exists in the repository on November 23, 2026. Evidence comes from the landing code, the local production build, a parse of the emitted HTML, and a spot check of comparable search results. The project documentation identifies local URLs, and no production homepage could be verified for this project.

**Assessment:** The highest priority is serving the homepage as complete HTML. The current build emits a shell with the title “TanStack Start Starter” and no landing content. After that, make the offer explicit in the title and H1, and explain who can use TalkTherapy and what happens after signup. Live SEO health remains unknown.

## Content and search intent

The strongest working homepage intent is **a speech therapy platform for patients, families, and clinicians**. The source supports appointments, practice and care records. A search spot check surfaced software products under “speech therapy platform” and direct care providers under “online speech therapy.” The distinction matters because the current primary action opens account registration. Confirm the audience, vocabulary, and demand with Search Console queries and customer language when available. [SpeakTX](https://speaktx.com/) · [Voca Quest](https://www.voca-quest.com/) · [Example direct care provider](https://anywherespeechandlanguage.com/services/online-speech-therapy/)

| Element | Suggested copy |
| --- | --- |
| Title | Speech Therapy Platform for Patients and Clinicians \| TalkTherapy |
| H1 | Speech therapy appointments and practice in one place |
| Meta description | Manage speech therapy appointments, practice in English or Filipino, and keep care resources and records together with TalkTherapy. |
| Hero lead | Keep track of appointments and care records. Practice speech exercises in English or Filipino and record and replay your practice. |
| Primary CTA | Create an account |

Start with two on-page content additions. **How TalkTherapy works** should explain the actual steps from account creation to the first appointment or exercise. **Speech practice in English and Filipino** should show a real exercise and explain recording and replay. A standalone feature page can follow if query data shows distinct demand and the team can illustrate the workflow with real product examples. Confirm service geography, signup eligibility, and clinical availability before targeting location or direct-booking queries. English and Filipino exercises alone do not establish separate localized homepage variants.

## Action plan and verification

1. **Make `/` independent of the session API and deliver complete HTML.** Inspect the anonymous response with JavaScript disabled. Expect HTTP 200, the TalkTherapy title and description, visible homepage copy, one descriptive H1, and an anchor to registration. Check ordinary signed-out, API-down, and signed-in visits.
2. **Update positioning and trust information.** Compare the title, H1, and signup destination. Confirm the onboarding copy against the actual signup and appointment flow, review the four feature descriptions in the default page state, and verify destination links.
3. **Verify the live search surface.** Once the production URL is known, inspect its status, host redirects, robots directives and headers, rendered HTML, and Google-selected canonical in Search Console. Test link previews on the target sharing platforms and check that arbitrary URLs do not return an indexable homepage shell.
4. **Establish a baseline.** Record Search Console impressions, clicks, and queries for `/` and review the volume and relevance of non-brand queries. Measure mobile LCP, INP, and CLS using field data when available and use a lab trace to diagnose asset costs. Track signup completion from organic homepage traffic if analytics are available.

## Verification limits and methods

- `bun run build` succeeded in `client/`. Parsing the 6,625-byte `dist/client/_shell.html` with jsdom confirmed an English document, responsive viewport, starter title, zero heading and anchor elements, and no homepage description, canonical, or JSON-LD. The same build emitted a permissive `robots.txt`.
- Checked route configuration, session error behavior, landing copy, links in source, and asset sizes. The live rendered DOM, HTTP redirects and headers, Search Console coverage, traffic, conversions, backlinks, mobile layout, and Core Web Vitals remain unverified. The local shell shows a rendering dependency, and the production indexing outcome is unknown.
